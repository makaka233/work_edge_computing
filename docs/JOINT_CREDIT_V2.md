# Proposed 联合学习修复：joint-credit-v2

## 备份与边界

改动前代码已在原分支提交并上传 GitHub：`123a0a3`。没有创建分支。
本版本通过 `train_dual_ppo.py --proposed-design joint-credit-v2` 显式启用。
未启用的新运行和旧 checkpoint 仍采用原来的模式，不静默升级。

保留 Slow PPO + Fast PPO，同时联合训练；Count、Stage、Placement 是 Slow
内部的三个动作头，不是三个新增智能体。没有专家动作、模仿学习、预选路径、
固定部署模板或人为副本上限。RAM/SSD、计算和共享 NIC 约束保持不变。
服务目录、节点参数、需求、接入网络、时限和 KKT 数值精度均不修改。
历史 runs/results/图片/checkpoint 不删除、不覆盖。

## 1. 阶段额度部署，而非全局预算加数百次 Stage 选择

新分配模式为 `stage-budget-v3`，实现位于 `edge_drl/agents/stage_budget.py`。

1. 所有有效阶段先覆盖至少一个副本。按在线资源装箱难度安排覆盖顺序，
   但每个覆盖节点仍由 Placement PPO 选择。不能用算法修复后的动作冒充
   PPO 采样动作；若覆盖不可执行，明确失败。
2. Stage PPO 在尚未处理且仍可追加副本的阶段中，学习处理顺序。
3. Count PPO 读取当前阶段及完整部分部署，采样连续 Beta 动作 `a∈[0,1]`。
   若该阶段当前最多还能放置 M 个副本，则追加额度为
   `min(floor(a*(M+1)), M)`，因此零追加和全部可行副本均可表示。
   存储采样的连续动作及其原始 Beta log-density，不能用整数的概率替换。
4. Placement PPO 逐副本从全部资源可行且未部署该阶段的节点中选择。
5. 每个阶段至多接受一次额度决策，之后不重新访问。已处理标记进入各头的
   决策前观测；即使额度为零，也不能把执行器状态藏在网络观测之外。

32节点、29个有效阶段时，Stage 的动作次数由数百次降到最多29次，Count
由一次全局预算变成最多29次阶段额度。**Placement 仍是逐副本决策**，没有
把整套部署压缩成一次动作，也不能据此承诺完整 rollout 按比例提速。
这减少了导致同一最终部署的重复交错顺序；没有把可行部署替换成固定候选集合。

新日志的 `budget_fraction` 是阶段额度比例的汇总，不再是旧版全局内存预算，
不能跨版本当作同一个变量比较。`quota_json` 记录各阶段的处理顺序、连续动作、
当时可行额度、实际额度及剩余资源。

## 2. 真实终端回报 + 部署前缀信用

新学习模式为 `prefix-credit-v2`。每个窗口仍只有一个真实部署回报；不会把
数百个动作宣称为数百个独立奖励样本。Actor 仅使用当轮 on-policy 数据，
Critic 回放仍只保存状态和真实窗口回报，不回放动作或专家标签。

显式把部分部署视为窗口内的内部决策过程：中间奖励为零，末端为真实窗口回报 R。
各头沿自身在该窗口中的因果顺序构造 prefix GAE，不能跨窗口或打乱后的样本构造轨迹。
Critic 始终用真实 R 拟合，不以代理计算成本训练价值标签。

- 训练初期可靠度为零，Actor 使用原始 Monte-Carlo `R-c*V_before`。
- 可靠度 r 只由**过去批次**的更新前 EV 得到，限于 `[0,1]`。
- `lambda=1-0.05*r`。用未缩放的旧价值构造 GAE，再以 r 混入其相对原始
  `R-V_before` 的修正；不能把历史校准倍率 c 当作 Bellman 价值缩放。
- 当 lambda=1 时，修正严格为零，仍是原 MC 优势；lambda<1 是常规的
  bootstrap 偏差—方差折中，不声称信用已精确或完全无偏。
- 当前回报不能用来决定当前 Actor 的可靠度、lambda 或校准倍率。
- 独立条件 Critic、有限近期回放、归一化 Huber、Actor/价值梯度隔离保留。

停止训练未参与此模式 Actor 信用的旧全局窗口 Critic，保留它的旧版本加载字段。
每10次更新记录一次首个小批的回报梯度和熵梯度范数；不是全数据梯度信噪比认证。
`slow_update_metrics_prefix_credit_v2.csv` 记录每头的信用、可靠度相关 lambda、
MC/前缀优势标准差、KL、样本覆盖和价值预测质量。

## 3. 目标统一与竞争观测

新 preset 默认以平均真实时延为共同目标。Slow 的 P95、部署 RAM/SSD 价格、
违约附加价格和早期共置奖励默认设零；预算仍由物理硬约束保证，时限本身不改。
仍保留 P95、违约和资源使用日志，绝不因此宣称满足所有现实 SLA。
显式传入的奖励参数会记录为定制目标，不能称为完全相同的平均时延目标。
旧 factorized 奖励项在团队回报模式中只是诊断，preset 将这些额外权重置零，
不再用调整未生效参数来解释学习变化。

新 Slow 观测中的计算代理同时考虑单请求工作和同一因果阶段上其他服务的竞争。
根据已知需求、部署和有效算力，使用容量加权路由近似构造节点需求平方根和；
候选增益也包括需求重新分布对其他服务的外部性。
这是轻量预测特征，不是精确联合 KKT 解、严格下界、实际请求路由或训练奖励。
旧模式的代理特征保持不变。

## 4. Fast 完整 epoch 的受控多步优化

`fast_update_chunks=4`：每个 epoch 将全部样本划分为最多4个随机负载混合块，
每块可再按原 minibatch 限制显存。每个块执行一次 Adam 更新，4个 epochs
最多接受16步，而非旧版4步。若某个在场负载组样本过少，自动减少块数，
保证每块覆盖所有在场组；不强行制造不存在的负载组。

每个完整 epoch 后，在原始整批数据上检查全批与分组 KL，仍使用原阈值。
超限恢复该 epoch 前的模型和 Adam，以相同分块、缩小步长重试；不能通过
放宽 KL 或遗留被拒绝的 Adam 动量获取更新。只有接受的步骤计入 optimizer_steps。
已有批次信用、逐请求 KKT 账本、gamma=lambda=1 与完整样本覆盖保持不变。

Fast 独立 Critic 增加直接的全局剩余批次信息和全部节点账本输入，而非只依赖
Actor 编码的池化向量。其价值梯度不进入 Actor，价值归一化继续保留。

## 5. 模型保存与选择

- `latest.pt`：每次更新后保存，可断点重续。
- `last.pt`：本次训练结束模型。
- `snapshots/update_XXXX.pt`：按原间隔保留。
- `best_rolling.pt`：最近80次以内、包含需求计算量校正的滚动训练分数最低模型。
  回归含自由时间趋势，避免把初期策略劣化完全解释成负载影响；它仍不是评估成绩。
- **`best.pt`**：默认每10次更新、首次和最后一次，用更新后的真实策略完成一个
  基准负载1.0的独立部署窗口探针，按探针平均时延选择。不是用更新前数据评价
  更新后参数，也不是把滚动146ms称为固定场景实测。

探针使用独立、固定且不进入训练的需求/请求随机流，在复制的智能体上运行；
完整保存并恢复 Python、NumPy、CPU/CUDA 随机状态。不会更新训练权重、优化器、
价值回放、计数、训练环境或需求随机流。它是低成本 checkpoint 筛选，
**不代表五场景最优、全秒认证或统计显著**，单探针仍可能过拟合。
`checkpoint_probe_metrics.csv` 和 checkpoint 的 `probe_result/selection_score` 记录依据。

## 6. 抽样与日志

训练与新版本评估共用时间维持长度计算。评估的 `--sampling-protocol auto`
对本设计选择 `training-equivalent-v2`，使用相同分层抖动及维持上限；同一测试点
所有方案使用相同采样随机流。旧 checkpoint 默认仍使用 `legacy-left-hold`，
可显式选择新协议，但不能将其结果说成旧结果的数值复现。
这只是机制统一，不证明6抽样与600秒全量在动态状态上等价。

`sampled_request_events` 是实际采样请求事件数；原 `requests/request_events`
仍保留代表时间权重以兼容旧统计。`settlement_steps` 是真实结算批次数，
`logical_steps` 是代表的仿真秒数。不能把加权事件数量当作独立训练数据量。
旧 CSV 续写按原表头匹配列，新增字段放入 `_extensions_v2.csv`，不破坏旧行。

## 启用、初始化与重续

```powershell
.\scripts\train_joint_credit_v2.ps1 -Updates 80
```

默认仅继承上一轮第320次模型的 Fast Actor，Slow、新 Fast Critic、优化器和更新
计数均从头开始，随后两者都参与联合 PPO；没有冻结 Fast 或分阶段训练。
这需要显式的 `--init-fast-checkpoint ... --init-fast-actor-only`，不能静默丢弃旧 Critic。
想完全随机初始化可用 `-FromScratch`；它不是与迁移初始化同条件的对照。

不能从旧 `budget-continuous-v2` 检查点直接完整续训到本模式，因为动作语义和
Fast Critic 形状改变。本模式自己的 checkpoint 支持原目录续训，保存/恢复
前缀可靠度、基线倍率、价值回放、优化器、模型选择状态和随机流。
