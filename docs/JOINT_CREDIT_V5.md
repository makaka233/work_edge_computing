# joint-credit-v5：追加部署、历史路由和独立图 Critic

本版本是供用户训练验证的改进实现，**没有经过新版正式性能训练，尚未证明优于DARP**。使用显式 `--proposed-design joint-credit-v5`；旧版本不自动升级。环境、部署RAM/SSD预算、时限、10分钟固定周期和公共共享NIC/KKT约束保持原值。

## 1. 完整部署过程

1. Placement学习硬覆盖的位置，保证每个有效阶段至少一个副本。
2. Stage决定第一轮阶段顺序；Count使用Beta区间概率输出完整物理范围内的整数额度；Placement逐副本选全部物理可行节点。
3. 首轮结束后，Stage可从剩余可行阶段中再次选择，或选择STOP；Count决定追加整数额度，Placement学习位置。零额度关闭该阶段，正额度至少消耗一个此前未部署的阶段—节点位置。

分配模式为`stage-budget-v6`，Count仍为v4设计已定义的可微Beta区间整数策略。完整范围0…M、实际执行整数的log-prob、PPO裁剪、KL检查与参数/Adam回退均保留。不引入DARP动作、专家标签、预设部署模板或候选数量截断。

新增全局观测为追加阶段标记和每阶段关闭标记，旧整数额度的M、已选量、剩余量和阶段访问标记继续保留。初始覆盖前清空这些状态。

有限终止：进入追加阶段时，设剩余物理副本位置上界为S、有效阶段数为K。每次非STOP决策或者消耗至少一个位置，或者关闭一个尚未关闭的阶段，所以至多S+K次非STOP决策；下一次必然结束。代码的循环上界用于验证此性质，不截断合法候选，也不是额外规划预算。STOP由Stage学习，不强制填满剩余RAM；有可追加位置不等于追加一定降低真实时延。

## 2. 因果链路与历史反馈

默认上下文`deployment-chain-v3`保留上/下游传输、入口局部性、带符号计算竞争、NIC余量及其他阶段资源机会损失代理。v6动作版本另外加入上一窗口真实结算历史：

- 节点新增6列：本阶段、上游阶段、下游阶段的历史路由占比，本阶段在该节点的平均计算/传输时延，以及该节点有无观测标记。
- Stage新增4列：上一窗口该阶段平均计算时延、平均传输时延、路由最大节点占比、有效观测标记。

时延按代表请求权重累计，传输包括该阶段入边链路和传播，不将无线固定接入成本混作节点计算成本。未观测节点的时延特征为0，同时明确观测缺失标记；不是认定未观测节点成本为0。

反馈只在窗口完成时发布；训练与冻结评估共用累计逻辑，各方案维护自己的历史。Episode切换清空。检查点保存上一窗口历史；完整恢复不丢失该输入。当前/未来请求结果不进入当前部署。历史路由属于旧策略与旧部署的观测，不宣称是新部署下Fast真实路由或精确反事实收益。

## 3. 独立结构化价值编码与短回放

`prefix-structured-v3`为Count/Stage/Placement分别建立独立价值网络：自己的全局、节点、边、图注意力和Stage编码，读取决策前状态与历史路由特征。它不使用Actor训练出来的图表示，Critic梯度不进入任何Actor参数。价值归一化只重标定最终仿射层，保持原始尺度预测。

Actor始终只使用当前轮动作、采样时旧概率和旧价值；真实窗口终端回报是训练标签。条件价值拟合在Actor更新之后进行；过去数据估计的基线倍率只用于未来更新。保留可靠度控制的前缀修正与MC回退。

默认价值回放从96窗口缩短到24窗口，保持每窗口最多8个状态及0.9更新衰减；记录行为更新编号、窗口编号和回放年龄。编号表示联合更新周期，不是完整策略权重哈希。可显式改变窗口数做消融。结构化Critic逐批累积同一加权全批梯度，限制激活内存，不缓存会变化的价值网络编码。

新增诊断：

- 按窗口等权的回报/缩放价值残差方差及其比值。
- 每10次更新，在更新前比较窗口score梯度的MC与因果基线版本，记录方差比和平均方向余弦。这是未标准化、未裁剪估计量的描述统计，不能冒充最终多轮PPO更新的方差认证；相邻窗口也不是独立统计重复。
- 每窗口累计log-ratio及可加KL代理，避免只看每动作平均KL。
- Actor/Critic更新耗时和价值回放最大年龄。

多部署分支LOO仍属于计划中“价值改进无效后”的条件备选，当前没有引入多分支结算开销，也没有证据决定应启用它。

## 4. 开销与学习率实验入口

rollout日志新增Slow规划、Fast调度和环境结算的墙钟时间；结算时间包含环境处理，并非纯KKT求解时间，Fast调度也包含自身的因果KKT计算。CUDA墙钟不做逐操作同步，不能当作精确GPU内核耗时。先根据用户实际训练计时定位开销，再决定缓存/增量优化。

启动脚本提供`-StagePlacementLrMultiplier 1|3`用于匹配种子、初始化和预算的受控实验，默认1；不提高KL阈值，不强行追求熵下降。当前没有执行此性能实验，也不声称3倍更好。

## 5. 用户启动训练

仓库中从头初始化两个PPO、完整320次训练：

```powershell
.\scripts\train_joint_credit_v5.ps1 -Updates 320 -Device cuda -Seed 2026 -PhysicalSeed 2026
```

脚本默认不读取任何旧模型。更换训练种子时保持PhysicalSeed固定，运行目录自动生成且拒绝覆盖。两个PPO始终联合训练。
添加`-DryRun`仅输出命令参数，不创建运行或启动训练。

显式迁移已有Actor作为开发实验起点：

```powershell
.\scripts\train_joint_credit_v5.ps1 -Updates 32 -Device cuda -InitFastCheckpoint <不可变来源> -InitSlowCheckpoint <同一来源>
```

支持旧Beta或Beta区间整数Count的完整Actor迁移，或者`-InitSlowActorScope stage-placement`迁移两个头。新增输入列置零，所有Critic、Adam和回放重新建立；迁移后概率律、动作阶段和后续观测可能改变，所以不是旧训练的完整续训。保存实际训练前`initial.pt`并记录来源。

独立包中：

```powershell
.\train_proposed.ps1 -ProposedDesign joint-credit-v5 -Updates 320 -Device cuda -Seed 2026 -PhysicalSeed 2026
```

同版本断点续训使用原运行名、`--load-checkpoint <latest.pt> --append-log --proposed-design auto`，updates表示追加次数。不能用旧v2/v3/v4检查点做v5完整续训。

## 6. 性能验收尚待训练

1. 当前固定Fast的Slow组件配对与各自联合Fast配对均需保留，DARP使用对应相同Fast。
2. 先对初始模型和受控训练后的模型做开发验证；所有已查看的2026/2027/2028/2030/2031需求种子不再作为独立最终确认。
3. 正式验收需要另设需求种子和训练种子、60分钟五场景28参数点，与DARP/HEFT/DPMS/MSO比较，报告逐点结果、失败、置信区间和种子差异，并另做更密时间采样核对。
4. v5是组合改进，单独贡献仍需消融；功能测试通过不构成收敛或性能提升证明。

部署周期自适应目前仅为用户提出的研究扩展，没有加入本版本环境。它需要单独匹配部署频率/开销、处理可变时长回报及采样，不能与上述固定周期验收混用。
