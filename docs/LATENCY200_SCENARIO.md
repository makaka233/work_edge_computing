# 低时延边缘分析场景：mec-latency200

## 1. 范围与兼容性

本档按已确认的候选设计实现：目标是**基准请求负载倍数 1.0 的加权平均物理任务时延向 200 ms 以下靠近**，而不是强制产生该结果。启用参数为 `--pressure-profile mec-latency200`，节点档 `jetson-ai-edge`，服务档 `edge-ai-latency200`。参数定义位于 `edge_drl/env/latency200.py`。

旧默认值、`mec-moderate`、`mec-stress`、`mec-realistic-constrained` 全部保留；不修改 PPO、动作、奖励、KKT、对比算法、抽样、日志与 checkpoint 结构，不删除任何实验记录。新档仍通过原有生成器、训练入口和配置继承流程运行。旧模型不能直接作为新环境训练已完成的证据；新一轮 Proposed / MSO 及其他方案必须使用同一新环境。

这些服务指边缘分析功能。AR 为识别及语义标注；机器人为点云障碍分析和导航规划；车联网为感知及非紧急规划。不代表运动到显示、电机控制、安全避碰闭环。一次请求不等于一段持续视频流。

## 2. 依据等级和单位

- **可追溯事实**：真实硬件型号、内存等级、接口；PCM/ECG/图像/点云的编码尺寸；公开模型结构及参数规模。
- **候选编码与工程估计**：JPEG 大小、物体数量、结果格式、工作集和磁盘预留。不能称为对应真实应用的统一实测值。
- **待标定预算**：节点 `48/72/144 Gcycle/s`、各阶段 Gcycle。保持既有模型 `时间 = 工作量 / 分配速率`；这里是有效吞吐的归一化量，**不等于 CPU 物理周期，也不能把 GPU TOPS 换算为 Gcycle/s**。异构硬件统一倍率是原模型的简化，尚未建模每种算子不同的硬件加速率。

MB 使用十进制 `10^6 bytes`，Mbps 除以 8 得 MB/s。内存/存储沿用原代码 GB 记账。计算候选以 NX 的 `72 Gcycle/s` 为参考，通过 `C = 72 × 候选独占执行秒数` 归一化；对应模型、精度、硬件及批大小的实测缺失时，不应声称全表均为真实性能测量。

### 逐服务输入与阶段含义

1. **语音**：11 秒 16 kHz 单声道 16-bit PCM = .352 MB；特征为 Whisper 80×3000 float32 padded log-Mel（.960 MB），随后 base 识别输出文本。base 是 74M 参数，约 1 GB VRAM 的公开参考；300 ms 候选推理预算尚非该设备该音频的实测。[Whisper](https://github.com/openai/whisper)、[音频实现](https://github.com/openai/whisper/blob/main/whisper/audio.py)。采集11秒不计在处理时延内。
2. **AR**：候选一帧 1280×720 JPEG，.300 MB 是质量/场景相关估计；解码、letterbox 后 640×640 RGB uint8 = 1.2288 MB；YOLOv8n 检测/NMS；语义标注输出，不包含持续渲染或显示响应。[YOLOv8](https://docs.ultralytics.com/models/yolov8/)。
3. **视频检测**：候选单帧 JPEG .152 MB 来自 COCO8 的 8 张示例文件大小均值（不是整个 COCO 分布）；640×640 RGB uint8；YOLOv8s 检测/NMS；结果编码。[COCO](https://cocodataset.org/)、[COCO8](https://docs.ultralytics.com/datasets/detect/coco8/)。
4. **工业**：1024×1024 uint8 灰度图 = 1.048576 MB，取 1.049；保持输入分辨率而非为了降时延裁剪；ResNet18 多尺度异常分析、256×256 float16 热图（.131072 MB）、缺陷区域报告。仅对应灰度质检子类；热图分辨率/模型精度需验证，不代表所有彩色质检。[MVTec AD 原始数据说明](https://www.mvtec.com/fileadmin/Redaktion/mvtec.com/05_research_teaching/datasets/mvtec_ad.pdf)。
5. **交通**：.300 MB 单帧 JPEG 是工程估计；640 RGB、YOLOv8s、当前帧占有/计数，不把单帧称为时间段车流统计。
6. **零售**：.250 MB 单帧 JPEG 是工程估计；640 RGB、场景训练的 YOLOv8s、事件候选。通用 COCO 权重不等于商品识别模型；不承诺多帧事件确认。
7. **机器人**：.210 MB 参考 PCL 192721 彩色点压缩示例约 204 kB；解压后紧凑 xyz/color 每点16 bytes约3.084 MB；局部代价地图100×100 float32=.040 MB；导航路径。压缩包含量化，不是无损任意点云都能达到此比率。[PCL 示例](https://pointclouds.org/documentation/tutorials/compression.html)。
8. **生命体征**：10秒、12导联、500 Hz、16-bit ECG = .120 MB；转float32=.240 MB；1D ResNet 71分类概率=.000284 MB；异常报告。与 PTB-XL 格式对应，不宣称医疗报警合规。[PTB-XL](https://physionet.org/content/ptb-xl/1.0.3/)、[模型基准](https://github.com/helme/ecg_ptbxl_benchmarking)。
9. **巡检**：.148 MB 参考 VisDrone2019-DET-val 全部548张原始JPEG的文件大小均值 .148195 MB，中位 .142724、P95 .235335、最大 .479237；上传不额外降分辨率。预处理为1280 RGB uint8=4.9152 MB，YOLOv8s1280与地理报告；这是阶段张量估计，不意味着原图均为相同尺寸。[VisDrone](https://github.com/VisDrone/VisDrone-Dataset)。
10. **车联网**：KITTI 点云格式提供 xyz/intensity 四float32字段参考；10万点采用本候选 int16厘米坐标×3 + uint16 intensity，并预留1KB元数据，约 .801 MB；解码float32=1.600 MB；PointPillars和非紧急轨迹建议。**.801不是KITTI原始文件大小**，量化损失及安全适用性需验证。[KITTI](https://www.cvlibs.net/datasets/kitti/raw_data.php)、[PointPillars](https://arxiv.org/abs/1812.05784)。

YOLO FP16 加速存在公开设备级参考，但各预算并非直接抄录测试：[TensorRT 示例](https://docs.ultralytics.com/integrations/tensorrt/)。DeepStream 报告是完整流水线吞吐，**不能简单取 FPS 的倒数当单请求时延**：[NVIDIA DeepStream 性能](https://docs.nvidia.com/metropolis/deepstream/7.1/text/DS_Performance.html)。检测框输出的 50/100/200 等数量是典型数据量假设，不是截断实际结果的代码上限。仿真只模拟工作量和传输量，不运行这些真实模型。

## 5. 不变的需求、随机与时限语义

12000用户，20%活跃，每活跃用户1.75请求/分钟，traffic_scale=1；stationary沿用原日曲线均值因子约 .818118，所以基准实际期望约 **57.268请求/秒**，不是70。60分钟episode，10分钟部署窗口。训练连续负载分层仍为 `.65:.80,.80:1.00,1.00:1.20,1.20:1.45`，概率 `.20,.45,.25,.10`；基准1.0的判断不能拿整个混合训练平均替代。

保留原随机过程：目录输入/计算±15%，输出±20%，内存±8%，存储±10%，时限±10%；单请求输入/输出lognormal sigma=.35、计算sigma=.30。虽字段名有 mean，原采样器以这些中心值为**中位数**，因此算术期望分别高约6.3%、4.6%；本轮不修改采样器或随机数顺序。标称定长编码只是规模锚点，生成的请求仍是统计扰动，不是精确执行固定尺寸张量。需要固定格式的数据集重放属于下一步建模工作。

基础时限、deadline_scale=2.75 和请求时限 `.05–.60 s` 截断均未改。这里截断的是业务时限，**不是物理时延**；超过.60秒仍如实结算。不能据此宣称真实SLA达标。最终阶段结果返回用户、传感器采集窗口、模型精度不在当前物理时延度量内。

## 6. 理论下界的正确口径

单请求、最快节点独占、无转发的理想下界：

`L_s = .010 + input_s / 37.5 + sum(C_s) / F_max` 秒。

seed=2026的32节点按17/10/5抽取，含计算扰动总容量约2283.493 Gcycle/s，最快154.175。用服务标称值和该seed的需求比例加权，上传约18.960 ms，单请求独占下界约58.594 ms。**这不是一秒内约57个请求同时结算的可达平均值。**

一秒批次的多请求KKT计算放松下界，按原串行阶段p分别结算：

`S_p = sum_i(m_i * sqrt(C_ip))`

`LB_batch = [sum_i(m_i*(.010 + input_i/37.5)) + sum_p(S_p^2/F_total)] / sum_i(m_i)`。

来自 `sum_j(S_pj^2/F_j) >= S_p^2/sum_j(F_j)`。忽略部署、节点整数映射、入口/阶段链路与传播；原KKT/EWMA仍保留。对**具体请求批次**才构成相应物理结算的放松下界，不能把期望值称为每批通用下界。

标称目录、57.268 req/s、服务比例使用seed2026，50000批独立Poisson抽样（分析seed20261012）且按请求数加权：下界约**127.325 ms**，其中计算108.363、接入18.962。若总有效计算容量仅80%/60%，同一放松分析约154.416/199.567 ms。目录/请求随机工作量、EWMA折减、部署限制和传输会进一步改变实际结果；这说明小于200 ms存在候选预算空间，不证明训练一定达到。

实现后的seed2026目录另做解析核对，保留原请求lognormal扰动。在独立Poisson到达假设下，`E[S_p²] = sum_s(lambda_s * E[C_sp]) + (sum_s(lambda_s * E[sqrt(C_sp)]))²`。计算预算中位数为c时，`E[C]=c*exp(.30²/2)`，`E[sqrt(C)]=sqrt(c)*exp(.30²/8)`。以期望请求数加权的放松平均约**129.419 ms**（计算109.815、接入19.604）；容量80%/60%时约156.872/202.629 ms。这仍忽略网络和部署约束；容量折减后达到200 ms的预算余地很有限。

回归测试另按生成的真实目录/请求验证该不等式，并检查超过时限的物理时延不被截断。正式结论必须来自新环境训练及基准负载测试，不从理论值或旧checkpoint直接推定。
