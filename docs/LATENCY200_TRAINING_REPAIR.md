# latency200 训练修复记录

## 修复前备份

基线：`e9ddbdbdbea756204079157024925830d07859a5`。
备份分支：`codex/backup-latency200-before-credit-fix-20261012`。
备份包含新场景参数、接入入口、设计文档及回归测试；历史 runs/results 保留原地，不加入源码提交。

## 已确认问题

1. Fast 的前缀 KKT 增量成本能望远镜求和，但请求末尾 done 截断了较早请求对较晚请求的信用。
2. Fast 图编码器被原始尺度的 Critic MSE 同时更新，整轮 KL 检查不能防止首轮超调。
3. Slow Count 的窗口状态未显式包含服务成本，Stage 的两次首批探测只覆盖少量新增副本。
4. 新场景降低部署工作集，扩大计算量异构性；工程预算仍需真实设备标定。
5. 原环境是即时批次结算加 EWMA，而不是显式任务队列；逐边 NIC 限速不等于节点聚合 NIC 约束。

## 本轮实施边界

新增显式、可存入 checkpoint 的训练修复版本；旧默认网络维度与 checkpoint 行为保留。
修复 Fast 批次学习边界，隔离价值梯度并归一化价值目标，控制每次优化的 KL；补充 Slow 成本观测与窗口信用。
修复首末窗口日志聚合。
不修改十类服务参数，不人为设置固定预算/预选路径，不弱化对比方案。
上段是最初的实施范围；用户随后要求全部四项改进。现在已扩展到聚合 NIC、可审计预算与抽样校准，不再沿用“NIC留待后续”的范围。
真实硬件标定不能由代码测试替代，仍是明确未完成项。以下是已实现的代码与数学验证，不是已经完成设备实测的声明。

## 1. Fast跨请求信用与轨迹边界

新训练版本为 `batch-credit-v1`；`mec-latency200`的新训练自动启用，其他档默认保留legacy。旧checkpoint恢复时自动继承其版本，不能把旧模型直接当新维度模型续训。

- 同一秒的全部请求构成一个学习轨迹，只在最后一个请求的最后一个阶段终止；下一秒是新的结算批次。60分钟Episode和10分钟部署窗口没有缩短。
- `gamma=1, lambda=1`，回报包含该动作后续造成的整批KKT成本，而不是在每个请求尾部截断。
- 物理增量奖励为 `-reward_scale * ΔJ`。原账本存的是 `ΔJ/m`，现在先乘回物理请求数m；样本权重仅保留代表时间dt，不能再乘m一次。
- 六个额外全局观测描述剩余请求规模、计算量、上传量、中间传输量、同服务比例和事件数。这是观测增强，不声称已表达完整底层物理状态。
- 仍由PPO在全部合法节点上学习，不用固定预算、预选路径集合或算法动作替换actor。

## 2. Fast Critic尺度与KL

- Critic读取`detach`后的图编码，价值误差不再更新Actor共享特征。Actor与Critic分别裁剪梯度。
- 归一化价值目标，并通过输出层仿射调整保持原始单位的价值预测不变；Adam的一阶/二阶矩同时调整。归一化状态写入checkpoint。
- minibatch现在用于限制显存：每个epoch汇总全rollout加权梯度后只做一次Adam step，各负载组都先参与。
- 更新后测量全批与各负载组KL；超限同时还原参数与Adam状态，用同一梯度缩小步长再试。最多7次尝试，仍失败就保留更新前状态。步长回溯不是长期学习率退火，也不是回退到历史best模型。
- 日志新增回溯次数、接受步长、价值目标均值/标准差；`optimizer_steps`表示接受的step，而不再等于minibatch数。

## 3. Slow成本、条件基线与Stage覆盖

- Count/Placement/窗口critic的全局状态加入每服务的计算成本、上传量、中间传输量、RAM/SSD占用；Stage还增加阶段输入输出量。
- Count、Stage、Placement各自用其**决策前状态**预测本窗口回报，作为动作无关的条件基线；价值头分离梯度、训练归一化目标并保存尺度。
- 每个部署动作都得到实际完整窗口团队回报，不再把没有进行副本消融探测的Stage收益默认成零。消融仍可作诊断，但不控制这些动作是否获得训练信用。
- 跨服务不再按被选中的服务阶段居中而抹去阶段选择差别；可变长度部署序列保留完整score-function求和的相对权重。
- 明确优化的是当前部署窗口的成本。未来窗口重新部署与EWMA负载状态的长时域信用尚非本版本目标，不把窗口局部回报称为精确长期MDP回报。
- 新增`slow_stage_team_credit_fraction`，区别于旧的稀疏消融覆盖率。

## 4. 资源预算、抽样与网络分别校准

### 资源预算

`audited-v1`仍使用已批准的十类服务输入、阶段计算与传输规模，不为降低时延再缩小任务。
阶段RAM拆成`resident_memory_gb + contexts * context_memory_gb`，磁盘为应用增量资产；两个上下文是预留策略，不意味着吞吐翻倍，也不是请求队列的并发保证。
原生成器的随机内存/计算目录扰动不再作用于审计表里的固定格式预算。原数值变成可核对的确定锚点。

请求分布改为算术均值对齐，不再把名为mean的预算当中位数。定长PCM、灰度图、ECG及固定张量保持尺寸；压缩图像/点数可变化，点云解压数据量与输入的点数变化关联。其他输出结果尺寸仍是统计模型，不是实际模型输出重放。

`--service-calibration-file`可导入schema-1实测/估计预算，完整文档进入metadata/checkpoint，保证后续评估不依赖可变外部文件。声称measured必须给出设备、功耗模式、精度、运行库、输入规格、测量文件和至少30个样本；接口检查不能验证提供数据的真实性。

参考：[TensorRT内存结构](https://docs.nvidia.com/deeplearning/tensorrt/latest/architecture/how-trt-works.html)、[Whisper参数与VRAM](https://github.com/openai/whisper)、[YOLOv8模型](https://docs.ultralytics.com/models/yolov8/)。模型权重、执行上下文与临时激活必须分别计量；公开权重大小不能代替某设备的峰值内存实测。

### 抽样近似

新档用每个时间分层内的随机秒，避免永远取区间左端；代表时间仍仅用于统计权重和EWMA时间推进，不把请求数扩大成100倍来算瞬时KKT。
默认最多维持一个样本15秒；因此10分钟窗口请求6个样本时，**实际至少40个样本**，启动输出会明确打印requested与effective。要保留旧近似可显式`--sampling-max-interval-seconds 0 --temporal-sampling-mode left-hold`，但不能声称6秒与600秒等价。
在IID、恒定、未截断的利用率假设下，EWMA稳态方差相对逐秒更新放大为`tanh(dt/(2τ))/tanh(1/(2τ))`。τ=60秒时，维持100秒约81.9倍，15秒约14.9倍。缩短维持时间降低误差，不意味着恢复了全秒状态分布；新资源报告同时给出该解析诊断。

`scripts/calibrate_environment.py`冻结策略与部署，在同一完整请求轨迹上比较全秒和不同抽样数，报告时延误差、请求数误差和节点/链路负载RMSE。筛查阈值5%时延误差与0.05负载RMSE仅为工程标准，不是统计或物理保证。60秒测试不能认证60分钟动态。

该仿真仍是流体资源共享与EWMA负载记忆，不是完整的请求排队、丢弃、未完成任务跨秒传递模拟。没有通过一个人为排队公式假装补齐这些语义。

### 网络约束

新档默认`shared-nic`。每个串行传输阶段解：

`min Σ_e S_e²/b_e`, `0<b_e≤B_e`, `Σ_out b_e≤NIC_i`, `Σ_in b_e≤NIC_i`。

NIC为全双工、分别限制发送和接收；容量单位MB/s，原1/1/10GbE乘0.8后为100/100/1000MB/s。
固定端口对偶变量时，`b_e=min(B_e,S_e/sqrt(u_src+v_dst))`；向量化对偶坐标迭代，并用可行原始解与对偶下界间隙检查精度。求解失败显式报错，不静默使用突破NIC的结果。
边内请求仍按平方根比例分享该边的b_e。环境最终结算与Fast所选动作的前缀奖励用同一求解器，增量求和与联合成本闭合。候选动作特征使用轻量端口共享近似，不把它称为精确最终成本，也不借此替Actor选动作。
Equal-share/learned-share对照保留自己的分配规则，再作相同端口可行性缩放，不得突破NIC。跨端口外部性日志只是诊断近似，不再声称精确差分奖励。

网络参考：[Nano/NX千兆接口](https://docs.nvidia.com/jetson/orin-nano-devkit/user-guide/latest/hardware_layout.html)。仿真仍不含共享无线空口、重传和包级交换队列；300Mbps是单请求有效接入候选，而非所有用户同时获得该速率的保证。

## Rollout加速（vector-features-v1）

- 静态边特征改为数组运算，并按场景缓存；快/慢Actor共享同一缓存入口。Slow负载列保持实时更新。缓存核对矩阵快照，场景重置、拓扑/带宽/传播原地修改都会失效，不能用旧数据解释新场景。
- 保存全部物理节点对的路由索引与传播和。这只是原有网络路由器的索引，不是K条执行路径、部署模板或动作候选裁剪。
- 新Fast模式将当前阶段/下游阶段的候选代理成本一次计算成矩阵，保留原公式与全部可部署节点；旧标量实现保留为旧模式和等价性测试的参考。
- 实际选择动作后的NIC增量奖励仍调用精确结算求解器，账本仍逐请求/逐阶段更新，没有通过微批、延迟更新、近似奖励或放松约束提速。
- NIC对偶更新跳过非绑定端口，35次二分只计算绑定端口的行。可行性投影、原始-对偶间隙容差1e-7及错误处理保持不变。
- 新模式停止计算未用于训练的Fast局部regret、Slow逐请求局部marginal和副本消融。旧模式继续原逻辑。新训练默认关闭Oracle诊断；需要时仍可显式启用，它不参与训练目标。
- 不减少12个窗口/2个完整60分钟Episode的每update采集量；40样本/窗口和15秒维持上限保留。不在本轮引入多进程采集。

性能实测：同一CPU策略、部署、8个请求、24次阶段决策，静态路由预热后三次测量的中位数，标量候选特征0.9256s，向量候选特征0.3646s，约2.54倍；执行节点路径一致。该对照双方均已使用静态边缓存与加速NIC求解，不能把2.54倍当作完整训练/GPU速度保证，也不能直接与不同初始化的此前计时比较。
等价性测试覆盖边特征、实时负载、缓存失效、每节点候选特征、掩码后的状态、随机动作、logprob、value和精确奖励。训练metadata记录`rollout_acceleration_version`，不改变checkpoint网络维度。
加速改动全量回归242项通过，最后补充Fast旧regret跳过逻辑后专项20项再次通过。训练/恢复入口仍可用，未自动启动大规模训练，未创建分支或删除实验记录。

## 真实规模启动中断修复（shared-nic-certified-v2）

用户的`latency200_accel_s40_u80_20261012_233930`在首个窗口2.5%处中断，并非命令拼接或PPO更新错误。用相同seed2026、32节点、12000用户、CUDA及训练参数复现：共享NIC双端口对偶坐标算法达到300次迭代后，相对原始-对偶间隙仍为2.93e-6，超过1e-7验收要求。原报错`violation=1`实际表示最大端口容量比例约为1，不是超出容量100%。小场景的等价性/回归测试不足以覆盖这一真实规模数值退化问题。

修复保留原凸优化目标、链路容量、全双工发送/接收NIC约束及1e-7精度证书。常见情况继续走快速对偶坐标法；32轮仍未获得证书时，改用尺度归一化后的联合对偶L-BFGS-B，避免双端口对偶相互替代造成的缓慢收敛。只有可行原始解与对偶下界满足同一验收条件才返回，绝不以独立链路分配、放宽容差或忽略端口替代。联合求解使用项目已有SciPy依赖，优化器的success标志本身不能代替证书。

训练metadata新增`network_allocator_version=shared-nic-certified-v2`；checkpoint网络结构、学习率、奖励、采样数和60分钟Episode保持不变。Fast前缀信用与环境最终结算仍调用同一求解器。报错字段改成明确的`max_port_capacity_ratio`。

真实失败输入固化于`tests/fixtures/shared_nic_training_failure.json`，覆盖冷/热启动、端口和链路可行性及原始-对偶间隙；强制切换联合算法时与坐标算法的目标值一致性也已验证。新增测试后全量245项通过，最后缩短切换预算后专项31项再次通过；另64组32节点随机网络求解均通过。不创建新分支，不删除失败运行目录或任何历史实验记录。

真实CUDA运行检查：保留相同60分钟Episode和40样本/10分钟窗口，完整采集首个窗口后，Fast接受4个epoch更新，Slow Count/Stage/Placement接受2/3/3次更新，checkpoint保存/读取均通过。该诊断主动在一个完整窗口后更新，**不是正式12窗口update或80updates收敛验证**；单窗口Slow返回方差极小导致标准化价值损失很大，不能拿该诊断的critic损失判断正式多窗口训练。GPU诊断采用最初300轮后切换的修复版本，随后改为32轮提前切换已通过专项测试，不声称完整CUDA时间属于提前切换版。窗口内精确求解的批总信用闭合最大数值残差1.92e-5秒，是有限精度原始-对偶求解误差，不能声称机器精度相等。结构化摘要在`results/calibration_four_fixes_20261012/nic_solver_runtime_repair.json`。

### 联合算法停机不等于精度证书（shared-nic-certified-v3）

用户第二次启动在首窗口约27.5%处仍报错。最终提前切换版复现同样的`relative_gap=1.02e-7`：L-BFGS-B因目标变化接近机器精度而报告success，并不保证物理问题的原始-对偶间隙已达1e-7。上一版完整CUDA检查使用300轮切换版本，没有覆盖最终32轮切换代码的完整窗口，这一验证缺口必须明确。

v3不降低验收要求。联合解未通过原有证书时，以其为初值继续精确端口根修正；若仍不达标，再进行更严格的联合细化和端口修正。所有返回分支仍使用同一可行原始解/对偶下界证书，优化器success不能替代它。只改变NIC求解过程，不调整任务规模、网络容量、PPO超参数或奖励设计。

第二组真实失败输入保存为`tests/fixtures/shared_nic_joint_stagnation.json`。冷/热启动均加入回归，同时模拟优化器错误地宣告成功，并验证修正后的约束与证书。该真实失败输入修复后的相对间隙约5.05e-9；32节点稀疏网络、不同上传/中间数据量组合的128组压力测试也纳入测试集。`network_allocator_version`记录为`shared-nic-certified-v3`。
