## 已确认问题

1. Fast 的前缀 KKT 增量成本能望远镜求和，但请求末尾 done 截断了较早请求对较晚请求的信用。
2. Fast 图编码器被原始尺度的 Critic MSE 同时更新，整轮 KL 检查不能防止首轮超调。
3. Slow Count 的窗口状态未显式包含服务成本，Stage 的两次首批探测只覆盖少量新增副本。
4. 新场景降低部署工作集，扩大计算量异构性；工程预算仍需真实设备标定。
5. 原环境是即时批次结算加 EWMA，而不是显式任务队列；逐边 NIC 限速不等于节点聚合 NIC 约束。

## 本轮实施边界

新增显式、可存入 checkpoint 的训练修复版本；旧默认网络维度与 checkpoint 行为保留。
修复 Fast 批次学习边界，隔离价值梯度并归一化价值目标，控制每次优化的 KL；补充 Slow 成本观测与窗口信用。
修复首末窗口日志聚合。
不修改十类服务参数，不人为设置固定预算/预选路径，不弱化对比方案。
不在本轮混入队列仿真或聚合 NIC 约束：它们会改变结算模型、KKT约束与实验可比性，需要独立建模验证。
真实硬件标定不能由代码测试替代，继续作为明确未完成项。
